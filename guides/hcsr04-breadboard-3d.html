    Wire / partFromTo

    Column numbers grow left to right and row a is nearest to you. You need the 400-hole breadboard and 4 male-female wires (you have 10). No male-male wires (still on order) and no soldering.

    How the data flows

    1. You type in the chat page (browser on the PC). It hands the message to the NATS server (Docker, on the PC).
    2. NATS sends it over Wi-Fi: PC → router → board. Both the PC and the board are on the HomeLab Wi-Fi.
    3. The board asks Ollama on the PC for an answer (same path) and runs the tools it picks, for example reading the HC-SR04 on D25/D26.
    4. The answer, and rule messages like "Object detected", go back the same way: board → Wi-Fi → router → NATS → chat page, which shows and speaks them.
    5. The USB-C cable carries only power and the serial port (COM5: flashing firmware, logs). On a power bank the board works exactly the same.

    Why the ESP32 sits beside the breadboard

    Its two pin rows are 25.4 mm apart. Pushed into a breadboard, it would cover all the holes on one side and leave only one row free on the other, so there would be no room to connect anything. The 170-hole mini breadboard works just as well for the sensor (any 4 holes in one row, one column per pin); this guide uses the 400-hole one.

    How accurate is this model?

    • Exact: 2.54 mm hole spacing, rows a–e / f–j, which holes are joined inside, every hole used, the ESP32's pin names and order, the HC-SR04 pin order (from your photos).
    • Simplified: part shapes are approximate blocks; the ESP32's pins point down, so its wires plug on from underneath; the power rails are not used in this build.
